# Ask Matt

Choose the smallest workflow that reaches the user's requested outcome.

| Intent | Useful skill |
| --- | --- |
| Stress-test an idea | grilling; grill-with-docs when recording domain decisions |
| Explore behavior or layouts | prototype |
| Investigate a factual uncertainty | research |
| Draft a specification or split work | to-spec; to-tickets |
| Implement an agreed change | implement; tdd when a test-first workflow fits |
| Diagnose a bug | diagnosing-bugs |
| Review a diff or architecture | code-review; improve-codebase-architecture |
| Explore a large uncertain effort | wayfinder |
| Configure tracker conventions | setup-matt-pocock-skills |
| Resolve conflicts or guide manual setup | resolving-merge-conflicts; wizard |

Use these as routes, not a mandatory lifecycle. A small fix need not become an interview, prototype, spec, and ticket series. Preserve progress already made and continue an implementation request through relevant verification.

Some skills are explicit-only. Recommend them when helpful; do not silently activate an explicit-only skill the user has not selected. Use the host's available skill mechanism for eligible skills, not an assumed tool named Skill.

Stop for a material user decision or missing authority, not merely because a phase ended. For an actual context handoff, see [PHASE-BOUNDARIES.md](PHASE-BOUNDARIES.md).

Other explicit helpers: grill-me (interview), handoff (portable notes), teach (learning), to-questionnaire (async questions), wait-what (re-explain). Domain-modeling and writing-for-agents apply to their respective document work.
