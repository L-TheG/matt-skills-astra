# Agent brief

Write the behavior an implementer should deliver and how to verify it. For a PR, describe what remains to change in its existing diff, not an instruction to rebuild it.

Include only useful sections: summary, current behavior, desired behavior, important interfaces or constraints, checkable acceptance criteria, and exclusions. Link primary context and relevant code paths as navigation hints. Verify them at writing time and avoid brittle line-by-line recipes.

A draft brief is not automatically the authoritative contract and does not publish itself. Mark unsettled decisions and reconcile it with the maintainer's request before an authorized state transition. Once published, verify the target and preserve existing discussion.
