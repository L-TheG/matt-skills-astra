# Optional HTML architecture report

When the user requests an HTML artifact, use a readable, portable document with a short summary, prioritized candidates, evidence paths, proposed interfaces, costs, and a recommendation.

Use before/after diagrams when they clarify ownership or dependency changes. Match the project's domain terms; generic module vocabulary must not override established names.

Prefer static HTML, inline styles, and simple SVG diagrams for offline portability. If a diagram library is genuinely useful, use a trusted supported version, safe rendering, and escaped source text. Do not fetch executable CDN scripts merely for decoration or enable loose execution of untrusted diagram content.

Verify rendering and links. Save to the requested artifact location and report it. The format does not require diagrams for every finding or prohibit explanatory prose.
