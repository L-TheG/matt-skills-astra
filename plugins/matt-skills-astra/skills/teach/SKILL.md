# Teach

Start with the user's learning goal and demonstrated prior knowledge. For a one-off question, teach directly; do not turn the current code repository into a course workspace.

Keep each lesson focused on a useful outcome. Explain the prerequisite knowledge, then use an exercise or retrieval question with timely feedback. Spacing and interleaving can support longer-term practice; exposure alone is not evidence of mastery.

Use current primary sources for changing or uncertain claims. Cite useful source material without burying the lesson in links. Recommend communities only when real-world feedback helps the user's goal and they want that involvement.

For a requested ongoing learning workspace, reuse existing materials and create only artifacts that earn their upkeep:

- [MISSION-FORMAT.md](MISSION-FORMAT.md): learning goal and constraints.
- [RESOURCES-FORMAT.md](RESOURCES-FORMAT.md): annotated trusted resources.
- [LEARNING-RECORD-FORMAT.md](LEARNING-RECORD-FORMAT.md): demonstrated learning and misconceptions.
- [GLOSSARY-FORMAT.md](GLOSSARY-FORMAT.md): terms the learner can use.

Use chat, Markdown, or an interactive HTML lesson according to the teaching need and requested format. Reuse existing assets when useful; do not build a component framework for one lesson. Quiz distractors should be plausible and avoid obvious visual giveaways, not obey exact word-count quotas.

Finish with a clear explanation or usable lesson and a suitable opportunity for practice.
