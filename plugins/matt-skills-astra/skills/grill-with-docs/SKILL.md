# Grill with docs

Use the available grilling and domain-modeling skills through the host's skill mechanism, loading their instructions before applying them. If unavailable, interview around concrete scenarios and record settled terminology and consequential decisions in the project's existing domain docs.

Ask only unresolved decisions that affect the design. Research discoverable facts yourself. Keep questions dependent on unanswered choices for a later round.

The output is a clearer design and agreed documentation, not an automatic implementation or issue publication. Stop when the important uncertainty for this request is resolved, or when the user ends the interview.
