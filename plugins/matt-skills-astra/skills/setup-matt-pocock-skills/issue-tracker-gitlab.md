# Issue tracker: GitLab

Use the repository's connected GitLab tools or glab CLI. Resolve the project and whether the target is an issue or merge request; they have separate number spaces.

Read the relevant record, discussion, labels, and diff. Verify installed command syntax and supported project capabilities before writing. Use safe multiline arguments or body files appropriate to the host.

Create, comment, assign, label, or close records only within the requested workflow. Preserve unrelated metadata and verify changed records.

For Wayfinder, use the existing parent/child convention, supported epic or blocking relationships, or explicit links and blocker lists. Availability can depend on GitLab edition and configuration. A closed blocker is satisfied only if its required outcome actually holds.

Draft locally if no external publication was requested or the tracker is unavailable. Missing setup is a write limitation, not a reason to stop read-only planning.
