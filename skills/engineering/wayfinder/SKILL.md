# Wayfinder

Use a map when an effort has enough uncertainty and dependencies to benefit from one; a simple task need not become an issue graph.

Keep three kinds of durable context:

- **Notes:** source pointers and relevant observations.
- **Decisions so far:** answers with rationale and supporting evidence.
- **Fog:** unresolved questions and areas not yet specified.

Represent useful next steps as research, prototype, grilling, or implementation tickets. A ticket states the question or outcome, completion evidence, and actual blockers. Size tickets by a coherent verifiable result, not a token budget.

The **frontier** is work whose necessary dependencies are satisfied and whose ownership permits action. A closed or canceled blocker is not automatically satisfied: check its resolution and impact. Honor existing assignments and collaboration conventions.

Advance the user's selected scope. Research discoverable facts, prototype genuine uncertainty, involve the user for product decisions, and implement authorized work through verification. Continue to the next eligible ticket when that is within the request; there is no one-ticket-per-session rule.

Use the existing tracker or local map. Create, assign, edit, close, or publish records only within the user's requested workflow. Reconcile invalidated work with a supersession note rather than silently deleting history. Verify writes.

End with what was resolved, evidence, and the next meaningful uncertainty or blocker. A handoff should preserve the map and source pointers without forcing a fresh session.
